# AutoMouseCursorHider 托盘与 WinForms 设置界面设计

## 背景

当前版本是无窗口、命令行控制的静默程序。它可以执行鼠标隐藏逻辑，但用户无法直观看到程序是否正在运行，也不方便修改隐藏延迟。本次改造将保留轻量的后台行为，同时增加可发现、可操作的托盘体验。

## 目标

- 程序启动后默认不显示主窗口，只在 Windows 系统托盘显示图标。
- 用户能通过托盘菜单确认运行状态，并执行打开设置、暂停/恢复、退出。
- 设置窗口采用 WinForms，使用数字输入框和上下调节按钮，支持小数。
- 鼠标移动后立即显示；静止达到设定延迟后隐藏。
- 退出、暂停和异常路径都尽量恢复鼠标可见状态。
- 保持低资源占用、无控制台窗口、无需联网。
- 以 .NET 8 WinForms 自包含单文件方式发布，避免用户额外安装 .NET Runtime。

## 非目标

- 不创建启动后常驻的大型主窗口。
- 不在托盘菜单中列出 2、3、4、5 秒等固定时长选项。
- 不加入遥测、网络服务、广告或第三方联网依赖。
- 不改变现有鼠标隐藏核心算法的基本语义。

## 用户流程

### 启动

1. 双击 EXE。
2. 程序创建单实例互斥锁；已有实例时激活设置窗口或提示程序已运行，不启动第二个后台实例。
3. 创建托盘图标和后台计时器。
4. 托盘图标以正常状态显示，鼠标隐藏监控开始工作。

### 托盘菜单

右键托盘图标显示简洁菜单：

- `打开设置`
- `暂停` 或 `恢复`（根据当前状态动态切换）
- `退出`

菜单不直接列出具体延迟数值。左键单击图标打开设置窗口，双击也打开设置窗口。

### 设置窗口

设置窗口保持小巧，包含：

- 当前运行状态文本：运行中、已暂停或即将退出。
- `隐藏延迟（秒）` 数字输入框，带上下调节按钮。
- 输入允许小数，使用当前 Windows 文化显示和解析，但配置文件使用不变的 invariant 格式保存。
- 合法范围 `0.1–3600` 秒，超出范围或非数字时显示就地错误提示，不能应用。
- `开机自启` 复选框。
- `应用`、`取消` 按钮。

应用延迟后立即重置本轮静止计时，避免旧计时造成突然隐藏。取消不改变当前配置。关闭窗口只隐藏窗口，不退出程序。

### 暂停、恢复、退出

- 暂停时停止隐藏计时，并确保鼠标可见；托盘菜单和图标提示反映暂停状态。
- 恢复时重新开始一轮完整静止计时。
- 退出前停止计时器、移除托盘图标、恢复鼠标可见状态，再释放单实例锁。

## 配置与开机自启

- 沿用当前用户配置位置，保存隐藏延迟和开机自启开关。
- 开机自启使用当前用户 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 项，不需要管理员权限。
- 写入注册表时只写入当前程序的绝对路径，并正确引用含空格的路径。
- 设置保存失败时保留内存中的有效配置，并在设置窗口给出错误提示；不静默覆盖已有数据。

## 技术方案

- 项目改为 Windows Desktop SDK，启用 `UseWindowsForms`。
- 使用 `ApplicationContext` 作为无主窗体的消息循环宿主。
- `NotifyIcon` 提供托盘图标、菜单和气泡提示；设置窗口为普通 `Form`，打开时复用单个实例。
- 鼠标监控与 WinForms UI 通过 UI 线程安全的状态服务连接，计时器使用 WinForms `Timer` 或等价的单线程调度，避免跨线程控件访问。
- 保留现有 Win32 P/Invoke 鼠标控制，并将显示计数恢复逻辑集中在控制器中。
- 发布配置为 `win-x64`、self-contained、single-file、无控制台窗口；不依赖网络或外部服务。

## 安全与可靠性

- 程序不提升权限，不修改系统范围设置。
- 所有用户输入先解析、范围校验，再更新运行时。
- 任何退出路径都尝试调用鼠标显示恢复；重复恢复操作必须幂等。
- 单实例互斥锁防止多个进程同时调用 `ShowCursor` 导致显示计数失衡。
- 托盘资源和计时器在关闭时确定性释放。
- 保留自动化测试覆盖配置解析、状态切换、启动项引用和鼠标显示计数。

## 验收标准

- 双击 EXE 后 3 秒内能在托盘看到图标，任务管理器中只有一个进程。
- 托盘菜单可打开设置、暂停/恢复和退出；退出后图标消失。
- 设置窗口可通过输入框或上下按钮设置小数延迟；非法值不可应用并有明确提示。
- 鼠标静止超过设定延迟后隐藏，移动后显示；暂停和退出时可见。
- 重新启动后配置仍保留；开机自启开关按选择生效。
- 发布的 EXE 在未安装 .NET Runtime 的 Windows x64 环境中可启动。
- 现有核心测试和新增托盘/配置测试全部通过。
